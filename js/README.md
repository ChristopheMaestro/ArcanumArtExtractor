# Module layout

Two pages:

- index.html is the app: the Atlas (map, items, library, quests, demographics) with the Asset Browser in its Files and Workshop frames. Its scripts are the classic (non-module) files of `atlas/`, loaded by plain `<script>` tags so the page also works from a file.
- asset-browser.html is the Asset Browser. Entry point: `js/main.js` (loaded with `<script type="module">`). It also runs on its own.

- atlas/     the app: atlas-app.js (index.html's script: screens, panels, library, quests, sound, the Files/Workshop frames), world-atlas.js (world-atlas.html's script: the map, embedded by index.html), game-scroll.js (the game's scrollbars, also put on the Asset Browser in its frame), modules-merge.js (joins the modules' maps to the others)
- atlas/data/ GENERATED by the scripts of toolbox/atlas/ (each file names its generator in its first line); re-run them rather than editing by hand. The pictures they make are in the top-level atlas/ folder; the Atlas plays music and sounds straight from data/sound/

- core/      shared DOM refs, config roots, app state, log, helpers (text-io: fetch/decode/memo/.mes tables, manifest: folder manifests, art-id: art type nibble)
- art/       .ART decoding, explorer, GIF builder, hex viewer, share links; the packer (packer-kinds = what an .art is for and its defaults, packer-guide = the hotspot preview on a greyscale tile and wall, packer-art-builder = the file writer, packer-ui = the dialog)
- explorer/  welcome screen, shared viewer shell, folder-tree (the one file list every category uses), generic data explorer, file-name search for the categories without their own, saved state
- ui/        the app shell (shell.js: top bar, left/right side bars, tool strip, details panel) and the collapsible file list
- mob/       .MOB schema, decoder, explorer, viewer, "Display on map"
- proto/     .PRO explorer/decoder/viewer, critter art-id resolution
- objects/   object art loading shared by map views (walls, critters, frames)
- sec/       .SEC parsing, tiles, iso math, walls, lighting, folder map viewer (a single .sec opens the folder map focused on it; sec-lod = sector miniatures (tiles, objects, roofs) drawn when zoomed far out; sec-terrain = world-map sectors generated from data/terrain through terrain.tdf, loaded on click; sec-npc-motion = the routes roaming NPCs follow under "Animate", derived from game/ai.c: waypoints, day/night standpoints, wandering; sec-nav = walkability of the map and the game's path-finding, which those routes are walked over)
- editor/    the .SEC map editor, which only runs when switched on: sec-folder-viewer (the folder map viewer and the editor itself), sec-writer (builds the exported .sec files, mapinfo.txt), sec-game-protos (GENERATED by toolbox/extract_game_protos.py: the prototype and flags the game gives each art), the house generator (sec-house-plan, sec-house-wfc, GENERATED sec-house-data / sec-facade-layouts / sec-facade-groups), sec-village-paths, world-editor-dialog (new worlds), sec-extra-tools (the Copy/paste, Roof, Light, Blocked tiles, Sector and Map tools: panels and behaviour, history entries `{ kind: 'fn', sec, apply(forward) }`), sec-sector-extras (a sector's tile scripts, properties and block list: editing, diffing, written again as 0xAA0004), sec-map-files (startloc.txt, map.jmp, map.sbf)
- text/      .DLG, .MES explorers and text-table search (scoped to the category being browsed: DLG searches dialogues, MES the text tables)
- scr/       .SCR decoder and explorer. scr-schema.js is GENERATED from the CE sources (script.h / script.c) by `python toolbox/gen_scr_schema.py`; re-run it rather than editing by hand

Frame-time readout: open asset-browser.html?perf (or set localStorage.secPerf = 1) to show ms per frame and objects drawn next to the map zoom.
